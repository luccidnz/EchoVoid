# Ech0Void Native V3 — Corrected Product Truth

## Core identity

Ech0Void is an experimental ITC / ghost-box-inspired **signal instrument**, not a spooky procedural synthesizer.

The instrument should feel as though the user is scanning, breaking, gating and disturbing fragments of recorded signal material. **Silence is a first-class part of the instrument.** A mode that constantly drones, chirps or produces synthetic vocal tones has failed the product target.

## Signal source model

### App output

The live ITC output is built from:

- short fragments cut from recorded human/radio source material
- forward and reversed playback
- rate changes
- gated silence
- overlap/echo where appropriate
- short static/noise windows for scan texture

The source recordings are bundled offline and chopped into micro-fragments. The live capture path must not play intact semantic sentences from those source recordings.

### Room microphone

The microphone is primarily a **separate room/EVP recording path**. It is not secretly fed into a fake detector and it is not used to fabricate a response.

Speaker bleed can still enter the room recording. Provenance timestamps exist so this can be reviewed.

## Engine truth

### EchoBox

- mostly quiet between events
- recorded human micro-fragments, not oscillator vowels
- single fragments may repeat as echoes
- higher Intensity increases response density and overlap
- Variation changes timing and playback-rate spread
- Texture changes how often extra layers appear
- high Sensor Mix can make quiet sensor periods quieter and sensor activity shorten the wait

### Field Drift

- recorded micro-fragments
- reverse-leaning
- rate jumps
- clustered bursts separated by quiet
- deliberate mute/dropout windows
- fragments may jump between different recorded source families

### Signal Scan

- ghost-box-style sweep bursts, not a continuous static bed
- each sweep consists of very short recorded windows and occasional short static gates
- each burst is followed by real silence
- higher Variation makes scan windows shorter/faster
- Intensity changes the number of scan steps and burst frequency

## Hard anti-drift rules

Do **not** reintroduce:

- continuous synthetic vowel/formant generators as the main voice source
- constant procedural chirps
- constant noise beds
- random dictionary words presented as external communication
- TTS pretending to be an entity
- AI-generated spirit messages in the live capture path
- fake sensor/anomaly values
- semantic claims that a sensor spike is a spirit response

## Working definition

A physical-phone build is not accepted unless:

1. there are obvious quiet gaps
2. EchoBox sounds like sparse/clustered recorded fragments with echoes
3. Field Drift sounds broken/reversed/jumpy rather than like a synth
4. Signal Scan behaves like short scanning windows followed by pauses
5. the three modes are immediately distinguishable by ear
6. Sensor Mix materially changes timing behaviour
7. room capture remains separate and replayable
8. every app-sourced audible fragment or static gate appears in the provenance ledger
